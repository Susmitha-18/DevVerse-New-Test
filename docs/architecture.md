# DevVerse — Storage Architecture

> **This document is MANDATORY reading for all contributors.**
> Every storage decision in DevVerse must comply with this architecture.

---

## Overview — Hybrid Storage Model

DevVerse uses a **Hybrid Storage Architecture** that separates cloud identity
from local developer data. This design protects user privacy, reduces cloud
costs, enables offline mode, and ensures developer credentials never leave
the user's machine.

```
Desktop Application
│
├── LOCAL: SQLite (better-sqlite3)
│   └── All project, workspace, and developer data
│       Stays on the user's computer. Always.
│
└── CLOUD: MongoDB Atlas (via Backend API)
    └── Identity, authentication, and minimal preferences only
        No source code, no credentials, no project files.
```

---

## Rule 1 — What Goes in MongoDB Atlas

MongoDB Atlas stores **ONLY** identity and session data:

### User Account
| Field | Type | Notes |
|-------|------|-------|
| `_id` | ObjectId | Auto-generated by MongoDB |
| `fullName` | String | Display name |
| `username` | String | Unique, lowercase |
| `email` | String | Unique, lowercase |
| `password` | String | bcrypt hash — NEVER plaintext |
| `profilePicture` | String | URL only — not binary |
| `accountStatus` | Enum | `active`, `suspended`, `deleted` |
| `createdAt` | Date | Auto-managed by Mongoose |
| `updatedAt` | Date | Auto-managed by Mongoose |
| `lastLoginAt` | Date | Set on each successful login |
| `lastActiveAt` | Date | Updated periodically |

### Authentication / Sessions
| Field | Type | Notes |
|-------|------|-------|
| `refreshToken` | String | Hashed — used for token rotation |
| `deviceId` | String | Identifies the device |
| `deviceName` | String | e.g. "MacBook Pro - Chrome" |
| `rememberMe` | Boolean | Controls refresh token lifetime |
| `expiresAt` | Date | TTL — auto-deleted by MongoDB |
| `ipAddress` | String | Last known IP |
| `createdAt` | Date | Session start time |

### User Preferences (Cloud)
| Field | Type | Notes |
|-------|------|-------|
| `theme` | Enum | `dark`, `light`, `system` |
| `language` | String | e.g. `en`, `fr` |
| `notifications` | Object | Email, push preferences |
| `desktopVersion` | String | Last synced app version |

### Connected Services Metadata
| Field | Type | Notes |
|-------|------|-------|
| `github.connected` | Boolean | Is GitHub connected? |
| `github.connectedAt` | Date | When it was connected |
| `docker.connected` | Boolean | Is Docker connected? |
| `aws.connected` | Boolean | Is AWS connected? |
| `groq.connected` | Boolean | Is Groq AI connected? |

> ⚠️ **IMPORTANT**: Connected Services metadata stores ONLY whether a service
> is connected and when. It NEVER stores tokens, passwords, or credentials.
> Those live in the local SQLite vault only.

## Rule 2 — What Goes in Local SQLite

The SQLite database lives at `~/.devverse/devverse.db` on the user's machine.
It is created automatically on first launch and is **never transmitted** to any server.

### Categories stored locally:

| Category | Examples |
|----------|----------|
| Projects | Project name, path, tech stack, metadata |
| Workspaces | Open files, layout, recent state |
| Git | Repositories, commits, branches, diffs |
| Docker | Images, containers, compose files |
| Build History | Build logs, results, duration |
| Deployment History | Local deployment records |
| AI Chat | Conversation history, generated files |
| Templates | Custom project templates |
| Environment Variables | `.env` contents (encrypted locally) |
| Secrets | API keys, tokens (encrypted locally) |
| Logs | Application logs, error logs |
| Monitoring | Performance history, metrics |
| Search History | Recent searches |
| Activity Timeline | User activity log |
| Reports | Downloaded reports |
| Notification History | Local notification log |
| Cached Data | API response cache, thumbnails |

---

## Rule 3 — What NEVER Goes to the Cloud

These items must **never** be transmitted to MongoDB Atlas or any external server:

```
❌ Source Code
❌ Git Repositories / commits / diffs
❌ Docker Images / containers / compose files
❌ Build Artifacts
❌ Deployment Files
❌ Project Files / workspace files
❌ AI Chat History
❌ Local Logs
❌ Secrets (API keys, passwords, tokens)
❌ Environment Variables (.env contents)
❌ AWS Credentials
❌ GitHub Personal Access Tokens
❌ Docker Credentials
❌ Any developer project data
```

## Rule 4 — Communication Flow

```
┌─────────────────────────────────────────────┐
│           Desktop Application               │
│                                             │
│  ┌──────────────┐    ┌────────────────────┐ │
│  │ React UI     │    │  Electron Main     │ │
│  │ (Renderer)   │◄──►│  Process           │ │
│  └──────┬───────┘    └────────┬───────────┘ │
│         │                     │             │
│         │              ┌──────▼───────────┐ │
│         │              │  SQLite Database  │ │
│         │              │  (Local Storage)  │ │
│         │              └──────────────────┘ │
│         │                                   │
└─────────┼─────────────────────────────────-─┘
          │ HTTP (Auth only)
          ▼
┌─────────────────────────┐
│    DevVerse Backend API  │
│    (Express + Node.js)   │
└────────────┬────────────┘
             │ Mongoose
             ▼
┌─────────────────────────┐
│    MongoDB Atlas         │
│    (Identity & Auth)     │
└─────────────────────────┘
```

## Rule 5 — Future Cloud Sync (v2.0+)

Cloud Sync will NOT be implemented in Version 1.

In future versions, an **optional, opt-in** cloud backup feature may be added:

- Disabled by default
- User explicitly enables it
- User chooses which data to sync
- Data is encrypted client-side before transmission
- User can delete cloud data at any time
